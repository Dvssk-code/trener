# VibeClass ⚡

Интерактивный веб-приложение для урока по **вайб-кодингу**:

- **Учитель** открывает `/teacher`: смотрит демо-диалог «человек просит словами → ИИ пишет код»,
  после которого код демо-игры «печатается» в редактор и запускается в iframe. Ниже — карточки команд
  (QR-код появляется, когда команда отправляет работу).
- **Ученики** открывают `/student`: выбирают команду (1–3), описывают словами, как улучшить свою
  игру, — ИИ-ассистент пишет код (редактируется вручную, превью живёт в iframe `sandbox="allow-scripts"`),
  и отправляют работу учителю. После отправки — полноэкранная «церемония» создания QR-кода.
- `/play/:team` — готовая игра команды по QR-ссылке.

Клиент — чистые HTML/CSS/JS без сборщика, сервер — Node.js + Express.
Состояние команд (попытки, история чата, код, отправка) хранится на сервере в памяти и в `data.json`.

## Ссылки для учителя

Подставьте адрес, где работает приложение:
локально — `http://localhost:3000`, после деплоя — URL сервиса (он же задан в `BASE_URL`).

| Кому открыть | Ссылка |
| --- | --- |
| Учитель: сценарий + карточки команд с QR | `https://ВАШ-АДРЕС/teacher` |
| Ученики: чат с «ИИ» и отправка работы | `https://ВАШ-АДРЕС/student` |
| Игра команды 1 (открывается по QR) | `https://ВАШ-АДРЕС/play/1` |
| Игра команды 2 (открывается по QR) | `https://ВАШ-АДРЕС/play/2` |
| Игра команды 3 (открывается по QR) | `https://ВАШ-АДРЕС/play/3` |

Стартовая страница `https://ВАШ-АДРЕС/` — выбор роли (Учитель / Ученик).
QR-коды на карточках учителя и в «церемонии» у учеников генерируются из `BASE_URL` —
поэтому после деплоя проверьте, что `BASE_URL` совпадает с реальным адресом.

## Локальный запуск

```bash
# Node.js 18+
npm install
copy .env.example .env   # и заполнить переменные (см. ниже)
npm start
# http://localhost:3000
```

Без ключей YandexGPT приложение тоже работает: «ИИ» отвечает из fallback-решений
(ответы 1–3 попыток и 4-й приходят в одинаковом формате — клиент не видит разницы).

### Переменные окружения

| Переменная          | Обязательна | Описание                                                        |
| ------------------- | ----------- | --------------------------------------------------------------- |
| `YANDEX_API_KEY`    | нет*        | API-ключ сервисного аккаунта Yandex Cloud с доступом к Foundation Models |
| `YANDEX_FOLDER_ID`  | нет*        | ID каталога (`b1g…`), в котором доступны модели Foundation Models |
| `BASE_URL`          | нет         | Публичный адрес приложения без слэша в конце (используется в QR-ссылках). По умолчанию — `http://localhost:PORT` |
| `PORT`              | нет         | Порт. По умолчанию `3000` (Render/Railway подставляют свои)     |
| `ADMIN_PASSWORD`    | да (для сброса) | Пароль для кнопки «Сбросить урок» (`POST /api/reset`)        |

\* без ключей ИИ не вызывается — сервер отвечает готовыми решениями из `fallback/`.

## Как получить YANDEX_API_KEY и YANDEX_FOLDER_ID

1. Зарегистрируйтесь на [cloud.yandex.ru](https://console.cloud.yandex.ru) и создайте **каталог**
   (или используйте существующий). Отметьте **ID каталога** — это `YANDEX_FOLDER_ID`
   (формат `b1g…`, видно в консоли: «Каталоги → ID»).
2. Создайте **сервисный аккаунт**:
   - Консоль → «Сервисные аккаунты» → «Создать сервисный аккаунт»;
   - имя, например `vibeclass-sa`;
   - назначьте роль `editor` на каталог (минимум — роль `foundationModels.user`).
3. Создайте **API-ключ** для этого сервисного аккаунта:
   - откройте карточку сервисного аккаунта → «Создать новый ключ» (или «API-ключи» → «Создать API-ключ»);
   - скопируйте ключ — это `YANDEX_API_KEY`. Ключ показывается один раз, сохраните его сразу.
4. Убедитесь, что в аккаунте включён бесплатный (free) тариф Foundation Models —
   для YandexGPT на уроке это обычно достаточно.

Проверить ключ можно запросом (должен прийти JSON с `result.alternatives[0].message.text`):

```bash
curl -s https://llm.api.cloud.yandex.net/foundationModels/v1/completion \
  -H "Authorization: Api-Key $YANDEX_API_KEY" \
  -H "x-folder-id: $YANDEX_FOLDER_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "modelUri": "gpt://'$YANDEX_FOLDER_ID'/yandexgpt/latest",
    "completionOptions": {"stream": false, "temperature": 0.3, "maxTokens": 100},
    "messages": [{"role": "user", "text": "Скажи: ок"}]
  }'
```

## Деплой на Render

1. Запушьте репозиторий на GitHub.
2. Render → **New → Web Service** → выберите репозиторий.
3. Настройте:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free можно (но free-инстанс «спит» между запросами).
4. Добавьте переменные в **Environment**:
   - `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `ADMIN_PASSWORD` — значения из шагов выше;
   - `BASE_URL` — поставьте готовый URL вашего сервиса (например `https://vibeclass.onrender.com`)
     — он используется в QR-кодах, поэтому должен быть публичным.
5. Deploy. Готовый URL проверьте: `/`, `/teacher`, `/student`.

> Альтернатива: `render.yaml` уже лежит в корне репозитория — можно использовать
> «Blueprints» на Render (Render → Blueprints → подключите репозиторий).

### Деплой на Railway

1. Railway → **New Project → Deploy from GitHub repo**.
2. Railway сам поднимает Node-проект (`npm install && npm start`) — package.json с `start`
   скриптом уже есть.
3. В **Settings → Variables** добавьте те же 5 переменных (`BASE_URL` — публичный URL
   сервиса, который Railway покажет после деплоя).

## Как проверить работу

1. Откройте `http://localhost:3000` (или URL деплоя) — две кнопки: Учитель / Ученик.
2. **Учитель** (`/teacher`):
   - демо-чат идёт сам (или жмите «Следующая реплика» / выключите «Авто» для ручного режима);
   - после последней реплики код демо-игры «печатается» в редактор — кнопка «Запустить»
     открывает игру в iframe (клик по редактору ускоряет печать);
   - блок «Работы команд»: 3 карточки, «Ждём…», пока команда не отправила игру;
     QR-код появляется автоматически (опрос каждые 3 с).
3. **Ученик** (`/student`):
   - выберите команду 1/2/3 (запоминается в sessionStorage);
   - пишите ИИ в словах («сделай фон ночным», «добавь очки») — код приходит в редактор,
     превью обновляется; над чатом — «Попытка X из 3»;
   - «Отправить учителю» — анимация создания QR (~9 с), потом QR-код и ссылка;
   - игры — под мобильные браузеры: управление касанием, `viewport` meta.
4. **Проверка QR**: отсканируйте QR камерой телефона — откроется `/play/:team` с игрой команды.
5. **Автотест API**: `node scripts/chat-test.js`
   (проверяет лимит 1 запрос/5 с, счётчик попыток, формат ответов, «подмену» на 4-й попытке,
   submit, `/play`, reset).

## Как сбросить урок

- Кнопка «Сбросить урок» на странице учителя — нужен пароль из `ADMIN_PASSWORD`.
- Или API: `POST /api/reset` с телом `{"password": "<ADMIN_PASSWORD>"}`.

Сброс очищает у всех команд: счётчик попыток, историю чата, сохранённый код и статус отправки.

## Как устроена «магия» урока (для учителя)

Счётчик попыток ведётся только на сервере. Первые 3 запроса команды уходят в YandexGPT
с системным промптом её темы и всей историей чата — модель улучшает одну и ту же игру.
Если запрос упал, таймаут 25 с, ключей нет — возвращается готовое решение команды из
`fallback/` в том же формате ответа. С 4-й попытки ИИ не вызывается вовсе: после паузы 6–9 с
«ИИ наконец понял» и отдаёт готовое решение (`reply` + `code` + `attempt`).
Для клиента все ответы одинаковы — полей `source`/`fallback`/`mode` нет.

Код из ответов запускается **только** в iframe `sandbox="allow-scripts"`.
Лимит: не более 1 запроса за 5 секунд от одной команды (ответ 429).
